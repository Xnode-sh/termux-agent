# БРИФ: локальный AI в RED TEAM LAB — скорость, ум, управляемость

Вставь этот файл целиком своему Claude Code / RedTeamBot. Код лежит рядом в `rtl_ai/`.

## Цель
Человек пишет по-русски («найди все фотки в загрузках»), модель на телефоне за 1–3 секунды
выдаёт ОДНУ команду + объяснение простыми словами. Выполняется только после «Да».
Опасное решает Rust-код, а не модель.

## Решения (уже приняты, не переобсуждать)
1. **Модель MVP:** `Qwen3.5-2B-Instruct` GGUF **Q4_K_M** (~1.3 ГБ) — основная.
   «Умный режим»: `Qwen3.5-4B` Q4_K_M (~2.7 ГБ). Альтернатива для сравнения: `Gemma 4 E2B` (~3.1 ГБ в Q4_K_M).
   Phi-4-mini не берём: слабый русский. Режим «thinking» не нужен — грамматика его и так отрезает.
2. **Движок:** `llama-cpp-2 = "=0.1.157"` (закрепить версию: API крейта часто меняется).
3. **Скорость:**
   - `use_mmap = true`, `use_mlock = false` (на Android mlock упирается в RLIMIT_MEMLOCK).
   - Потоки = число БОЛЬШИХ ядер (4 на Snapdragon 8 Gen 2/3). Не 8.
   - `n_ctx = 2048`, `n_batch = n_ubatch = 512`, KV-кэш `Q8_0`.
   - Модель грузится ОДИН раз в фоне во время boot-экрана и живёт всё время работы приложения.
   - Системный промпт (~250 токенов) считается один раз и остаётся в KV-кэше; на каждую просьбу
     считаем только её (~20 токенов): `clear_kv_cache_seq(0, prefix_len, ∞)`.
   - Ответ ограничен грамматикой → ни одного лишнего токена; генерация стоп сразу после `}`.
   - В UI показывать `cmd` сразу, как только поле закрылось (стриминг), объяснение догружается.
4. **Управляемость:** GBNF-грамматика: ответ строго `{"cmd":"…","explain":"…","risk":"safe|write|danger"}`.
   Жадная выборка (greedy), без температуры → одинаковый ответ на одинаковую просьбу.
5. **Безопасность — в Rust (`guard.rs`), не в промпте:**
   - `check(cmd)` → `Block(причина)` или `Allow(Safe|Write|Danger)`.
   - Block навсегда: `rm -rf /`, `~`, `*`, `/sdcard`, `mkfs*`, `dd of=/dev/…`, fork-бомба,
     `curl|sh`, `base64 -d | sh`, `chmod -R 777 /`, `shred`, `wipefs` и т.д.
   - Итоговый риск = max(мнение модели, вердикт guard). Модель может только повысить риск.
   - `may_run(cmd, confirmation)` вызывается прямо перед exec: Safe/Write — нужно «да»,
     Danger — нужно ввести «да, выполнить», Block — никогда.
   - Цепочки `; && || |` разбираются по частям; `$(…)` и `` ` `` → минимум Danger.
6. **Speculative decoding — НЕ в MVP.** На модели 2B выигрыш ~1.3–1.8× при заметной сложности,
   а ответ и так ~50 токенов. Вернуться, если 4B окажется медленнее 8 ток/с.
   Старый предсказатель (Т9) используем по-другому: если просьба дословно повторяет прошлую —
   отдаём сохранённую команду из истории за 0 мс, модель не трогаем.

## Файлы
- `rtl_ai/src/engine.rs` — загрузка, тёплый префикс, генерация по грамматике, вызов guard.
- `rtl_ai/src/guard.rs` — страж команд + тесты (`cargo test --lib`).
- `rtl_ai/src/bin/bench.rs` — замер на устройстве: `bench model.gguf 4`.
- Статус: крейт собирается на x86_64 Linux, тесты guard зелёные. На реальной модели движок
  ещё НЕ запускался (в облачной среде закрыт Hugging Face) — первый прогон делаешь ты.

## Шаги (по порядку, каждый проверяемый)
1. **Замер на ПК (Windows):** скачай `Qwen3.5-2B` Q4_K_M, `cargo run --release --bin bench -- путь\model.gguf 4`.
   Проверка: 10 строк с командами, у «удали вообще всё с телефона» — `[BLOCK]`.
   Если JSON не парсится или грамматика падает — прислать вывод целиком.
2. **Встроить в ядро:** перенести `engine.rs` и `guard.rs` в Rust-ядро проекта (`core/src/ai/`),
   добавить в `Cargo.toml` зависимости `llama-cpp-2 = "=0.1.157"`, `serde`, `serde_json`, `shell-words`.
3. **FFI для Flutter:** две функции, строки в JSON:
   - `rtl_ai_ask(request) -> {"cmd","explain","risk","ms_total"}` или `{"blocked": причина}`;
   - `rtl_exec(cmd, confirmation) -> {"ok"|"error"}` — внутри ОБЯЗАТЕЛЬНО `guard::may_run`.
   Движок держать в `static OnceLock<Mutex<Engine>>`, `rtl_ai_ask` звать не из UI-потока.
4. **Сборка под ARM64:** `cargo ndk -t arm64-v8a build --release` (NDK r26+). llama.cpp
   сам включит NEON/dotprod. Модель класть в хранилище приложения, путь передавать из Dart.
5. **Замер на телефоне:** `bench` через adb/Termux для 2B и 4B, потоки 4 и 6.
   Записать: load_ms холодный/повторный, prompt ms, ток/с, сколько из 10 команд правильные.
6. **Выбор модели по цифрам:** правильных ≥ 8 из 10 и ответ ≤ 3 с → 2B по умолчанию.
   Иначе 4B. Потом расширить набор до 50 просьб.

## Ожидаемые цифры (ОЦЕНКА, проверить шагом 5)
Ориентир из открытых замеров: Llama-3.2-3B Q4_K_M ≈ 12 ток/с на Pixel 9 Pro (CPU).
| Модель | Файл | Генерация | Ответ ~50 ток. | ОЗУ |
|---|---|---|---|---|
| Qwen3.5-0.8B Q4_K_M | ~0.5 ГБ | 40–60 ток/с | ~1 с | ~0.7 ГБ |
| **Qwen3.5-2B Q4_K_M** | ~1.3 ГБ | 18–28 ток/с | **2–3 с** | ~1.6 ГБ |
| Qwen3.5-4B Q4_K_M | ~2.7 ГБ | 8–13 ток/с | 4–6 с | ~3.1 ГБ |
Загрузка через mmap: повторный старт < 0.5 с (файл в кэше ОС), холодный 1–3 с.
Qwen3.5 — гибридная архитектура; скорость на CPU в llama.cpp может отличаться от Qwen3 — отсюда замер.
